# jev-browse

MCP server + CLI that hands browser goals to TypeSafe Jev (one `/v1/systemone` request per step) and returns a short summary to the calling agent.

## Commands
- `pnpm test`: offline unit tests (vitest), no key needed
- `pnpm typecheck` / `pnpm build` (emits `dist/`, copies `snapshot.js`)
- `pnpm verify`: live, headless Chrome + real Jev; needs `TYPESAFE_API_KEY` (costs credits, about 30 s). `JEV_MODEL=<profile>` runs it on another model via `OPENROUTER_API_KEY` (also Jev without `TYPESAFE_API_KEY`); `JEV_VERIFY_MIN_CONFIDENCE` overrides the threshold for experiments
- `pnpm verify:langfuse`: sixteen read-only jobs (an AI engineer's flows) in Langfuse's demo project from its home page, 3 runs each, recorded (video + described steps) into one `report.html`. Needs a Chrome signed in to cloud.langfuse.com on a debugging port (`JEV_LANGFUSE_BROWSER`, default `http://127.0.0.1:9333`); `JEV_LANGFUSE_RUNS`, `JEV_LANGFUSE_ONLY` narrow it. A pass needs the page check **and** status `done`
- `pnpm verify:real`: live public sites (Wikipedia, MDN, GitHub, Hacker News, npm, Booking.com, Google Flights), a fresh headless Chrome per run, 5 runs each; `JEV_REAL_RUNS`, `JEV_REAL_ONLY` narrow it. Bot walls are reported apart from failures
- `pnpm verify:checkout`: six shopper flows on SauceDemo (public practice shop; the harness starts each shopper run signed in (SauceDemo's session cookie, its published test account) and signs in on the login page only for `locked-out`, since jev-browse never lists password fields), a fresh headless Chrome per suite, 3 runs each, recorded into one `report.html`. `place-order` must end `needs_confirmation` on the overview, never on `/checkout-complete.html`; `missing-zip` and `locked-out` expect a hand-back. `JEV_CHECKOUT_RUNS`, `JEV_CHECKOUT_ONLY` narrow it
- `pnpm apps:forgejo:up` then `pnpm verify:forgejo`: eleven write jobs (labelled issue, comment, milestone, branch protection, plus two destructive jobs and one invalid name that must be handed back) on a throwaway Forgejo + Mailpit in Docker (compose project `jev-forgejo`, ports 3311/8325/1325). Each run starts from a reseeded demo and is judged by Forgejo's API. Needs Docker and `TYPESAFE_API_KEY`; `JEV_FORGEJO_RUNS`, `JEV_FORGEJO_ONLY` narrow it; `pnpm apps:forgejo:down` removes the stack and its data
- `pnpm verify:signup`: five sign-up jobs on the same Forgejo + Mailpit (sign up and activate through the emailed link, plus a full-name step; a malformed email, a taken username and a password handed over must be handed back). The harness types password fields (jev-browse never lists them) and reads the mail; accounts are named `signup-…`. Judged by Forgejo's admin API. `JEV_SIGNUP_RUNS`, `JEV_SIGNUP_ONLY` narrow it
- `pnpm mcp` / `pnpm cli -- --help`: run from source (Node ≥24 strips types natively)

## Layout
- `src/browser/`: CDP over the global WebSocket (`cdp.ts`), Chrome connect/launch (`chrome.ts`), guarded tab executor (`tab.ts`), and `snapshot.js` (vendored from jev-ultrafast; keep it diffable)
- `src/jev/`: action space, instructions, `box.ts` (Box answers → viewport rects → observed targets), `decide.ts` (one request: operation + speculative target/value/commit-risk/done-check heads), and `model.ts` (decision model profiles: Jev direct or via OpenRouter, plus Clef, Perplexity and GPT-6 Luna deciders: route, threshold, rules, screenshots, per-element risk)
- `src/task/`: `run-task.ts` loop and hand-back rules (incl. Box stops, rescue, Enter after search typing); `start-task.ts` connects the browser; `recording.ts` writes the optional human record (`recordDir`: screencast `run.mp4` via ffmpeg, step shots, `index.html`)
- `src/journeys/`: journey mapping; `screen-boxes.ts` adds Box primary-action hotspots and missing-from-DOM QA
- `src/mcp.ts`, `src/cli.ts`: entry points; `skill/`: the agent-facing skill; `verify/`: live e2e plus the fixture

## Invariants
- `tab.want(values)`: an off-screen link, button or row containing a supplied value is listed anyway (clicking scrolls it in), so a value the caller found in a table isn't lost below the fold.
- Model output only selects observed ids/keys. Never turn it into selectors, coordinates, scripts, or typed text. Box answers are mapped back to observed ids (`matchTarget`). The one exception is opt-in `allowCoordinateClicks`: BLOCKED, a confident box that matches no observed element, a hit-test at its centre, and the commit-risk gate.
- PRESS_ENTER is a fixed key, offered only right after typing into a search-like or filter field, and pressed only while that field still has focus. PRESS_ESCAPE is a fixed key offered only while an observed element is expanded (menu, popover, suggestions).
- Loop guards, generic rather than per site: a target covered by a popup layer (or while something is expanded) gets one automatic `dismissPopup` (Escape to the focused element, then blur and a synthetic outside press on `body`; focus is never moved first, it re-opens search suggestions); a target unreachable on an unchanged page is told to Jev on the 2nd miss and handed back (`blocked`) on the 3rd; an unsure WAIT still waits and an unsure PRESS_ESCAPE still presses; one action toggling the page A/B 4×, or the same element used 6 times in 7 actions, is `blocked`; a rejected DONE goes into history as "not visible yet"; 6 executed actions in a row under 0.5 confidence (waits and Escapes not counted) is `uncertain`; `done_when` ≥ 0.75 on 3 consecutive decisions is `done`; ≥ 0.9 once is `done` too, unless the next step confidently contradicts it (≥ 0.6 on another action, `fallback` screenshots): then one screenshot look must also clear 0.5.
- TYPE_TEXT types only `values[key]` from the caller. Choosing a field with no fitting value is fed back once (pick another step); the second time it becomes `needs_input`.
- A click that looks irreversible is handed back as `needs_confirmation`; the agent-facing text (tool description, reason, `skill/jev-browse/SKILL.md`) lets the agent set `confirm_irreversible` (one click each, honoured on a new session's first call) only for the action and target the user's own request names, and otherwise tells it to ask the user.
- A click or tap the page never received (no trusted `pointerdown`/`mousedown`/`touchstart` reached a counter registered before the page's scripts) ends the run `blocked` with that reason (`InputNotDelivered`, not a `StalePage`); it is never retried automatically, because a click the page did receive but the counter missed must not run twice.
- `done` requires the `done_when` Noul ≥ 0.5 when `done_when` is given. A BLOCKED whose `done_when` Noul is ≥ 0.5 is `done` too: nothing is left to do. An unsure next step on a screenshot-backed decision whose `done_when` Noul is ≥ 0.75 is `done` too.
- Verification asserts ground truth (`window.__fixture`, URL), never the agent's own status alone.
- Screenshot marks come only from snapshot rects and are removed before any input. The image never yields coordinates.
- Password fields are never listed; the request carries only whether each visible one is filled or empty (`password_fields`, plus a page-text line), never its value or length.
- Recorded (`sharp`) screenshots are for people only and never go into a request.
- Thresholds and rules are tuned per model. Jev's `NEXT_ACTION`, 0.3 and page-level commit risk are its verified baseline, so don't retune them on other models' data. Jev's chosen click is also judged by name (`pageRisk`), and it is risky if either question says so. The loop guards in `GUARDS` (run-task.ts) are Jev-only provisional baselines.
